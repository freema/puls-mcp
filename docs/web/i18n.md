# i18n (CZ / SK / HU / EN)

Stručný průvodce, jak v Pulsu pracovat s překlady. Cílem je: **žádné natvrdo zadrátované české stringy v komponentách a stránkách**, které mají alternativní jazykové varianty.

## Architektura

- **Locales:** `cs` (default, bez URL prefixu), `sk`, `hu`, `en`. Definováno v `apps/web/app/lib/locale.ts` (`SUPPORTED_LOCALES`).
- **URL strategie:** CZ je bez prefixu (`/pricing`), ostatní mají prefix (`/sk/pricing`, `/hu/pricing`, `/en/pricing`). Routy se generují v `apps/web/app/routes.ts` přes `LOCALIZED_ROUTES`.
- **Routy bez prefixu:** `/api/*`, `/auth/*`, `/oauth/*`, `/.well-known/*`, `/dashboard`, `/admin`, `/healthz`, statické assets. Viz `UNPREFIXED_GLOBAL_SEGMENTS` v `locale.ts`.
- **Volba jazyka:** přes `LocaleSwitcher` (header / footer) → `POST /api/locale { locale }` uloží cookie `puls_locale` (a `users.preferred_locale` u přihlášeného uživatele) → klient přejde na localizovanou variantu URL.

## JSON bundly

Každý jazyk má vlastní složku v `apps/web/locales/<lang>/`:

```
locales/
  cs/  (canonical — v něm vždy přidávej klíč jako první)
    common.json     # generic UI
    marketing.json  # public marketing/blog/pricing/contact
    legal.json      # privacy/terms/dpa
    dashboard.json  # logged-in app
    admin.json      # admin UI
  sk/, hu/, en/     # zrcadlí strukturu cs/, klíče které nejsou přeložené padají na cs/
```

**Fallback:** `getTranslations` v `app/lib/translations.server.ts` vždy načte CZ a hluboce sloučí jazykový overlay přes něj. Chybějící klíč v non-CZ tichá fallbackuje na CZ — žádný `[missing]` artefakt v UI.

**Cache:** v produkci se bundly cacheují per `(locale, namespace)`; v dev se čte ze souboru pokaždé.

## Použití v kódu

### V komponentě (klient i SSR)

```tsx
import { useTranslations } from '~/lib/i18n-context';

function PricingHeader() {
  const t = useTranslations('marketing');
  return (
    <>
      <h2>{t('pricing.heading')}</h2>
      <p>{t('pricing.subheading')}</p>
    </>
  );
}
```

### S proměnnou (template `{var}`)

```tsx
const t = useTranslations('marketing');
t('blog.pageOf', { page: 2, total: 10 });
// CZ: "Strana 2 z 10"  EN: "Page 2 of 10"  HU: "2. oldal / 10"
```

Placeholdery: `{name}` v JSON, předáno jako `{ name: 'Pro' }`.

### V `loader` / meta (server-side)

`useTranslations` jde použít jen v komponentě. V loaderu/meta funkci se sahá rovnou na server modul:

```ts
import { getTranslationString } from '~/lib/translations.server';
import { resolveLocaleFromPathname } from '~/lib/locale.server';

export async function loader({ request }: Route.LoaderArgs) {
  const locale = resolveLocaleFromPathname(new URL(request.url).pathname);
  return {
    metaTitle: getTranslationString(locale, 'marketing', 'blog.metaTitle'),
  };
}

export const meta: Route.MetaFunction = ({ data }) => [
  { title: (data as any)?.metaTitle ?? 'Blog — Puls' },
];
```

### Aktivní locale

```tsx
import { useLocale } from '~/lib/i18n-context';
const locale = useLocale(); // 'cs' | 'sk' | 'hu' | 'en'
```

## Bundly načítané v rootu

`apps/web/app/root.tsx` má konstantu `ROOT_NAMESPACES` — namespaces, které se předají do `<I18nProvider>` pro každou stránku. Pokud přidáváš nový namespace (např. `account.json`), přidej ho sem, jinak ho v komponentě nenačteš.

## Co lokalizujeme a co ne

| Lokalizujeme | Nelokalizujeme |
|---|---|
| Login + nastavení účtu | — |
| Dashboard a admin UI | Identifikátory toolů (názvy MCP toolů, slugy, klíče) |
| Meta tagy (title, description) přes loader | Hodnoty z DB (názvy tarifů, feature listy — pokud nemají i18n sloupec) |

## Přidání nového klíče — checklist

1. **CZ canonical:** doplň klíč nejdřív do `locales/cs/<namespace>.json`. CZ je zdroj pravdy.
2. **Přelož do `sk`, `hu`, `en`.** Stejný dotted-path. Chybějící klíč → fallback na CZ (UI bude vypadat napůl česky), takže to vždy doplň.
3. **Použij v komponentě:** `t('section.key')` přes `useTranslations('<namespace>')`.
4. **Otestuj všechny 4 locales:** `/`, `/sk`, `/hu`, `/en` (a sub-stránky `/sk/pricing` atd.).
5. **Meta tagy** (title, description) přes `loader` + `getTranslationString` — `meta` funkce nemá přístup k `useTranslations`.

## Přidání nové localized routy

V `apps/web/app/routes.ts` doplň pár `[path, file]` do `LOCALIZED_ROUTES`. Generátor automaticky vytvoří `/sk/<path>`, `/hu/<path>`, `/en/<path>` aliasy se sdíleným komponentem.

API/auth/oauth/admin/dashboard routy do `LOCALIZED_ROUTES` **nepatří** — locale tam jede z cookie, ne z URL.

## Locale switcher

`apps/web/app/components/locale-switcher.tsx`. Trigger ukazuje vlaječku + krátký kód (`🇨🇿 CZ`). Dropdown ukazuje vlaječku + plný název jazyka. Vlaječky jsou v `LOCALE_FLAGS` v `locale.ts` jako emoji — žádné obrázky ke spravování.

EN má 🇬🇧 (UK), ne 🇺🇸 — konvence v CZ marketu.

## Jak to celé visí dohromady

```
Request → root.tsx loader
  ↳ resolveLocale() z pathname / cookie / user.preferredLocale
  ↳ getTranslationBundles(locale, ROOT_NAMESPACES)
  ↳ <I18nProvider locale bundles>
       ↳ useTranslations('marketing')('pricing.heading')
            ↳ lookup v marketing bundle pro daný locale
            ↳ fallback na CZ pokud chybí
```

## Časté pasti

- **Hardcoded string v komponentě:** kdykoli vidíš česky text v `.tsx`/`.ts`, který je vidět na public stránce — patří do JSON bundle.
- **Klíč jen v CZ:** non-CZ stránka spadne na CZ text. Vždy doplň všechny 4 jazyky.
- **`useTranslations` v meta:** nejde, není v rámci providera. Použij `getTranslationString` v loaderu a předej přes `data`.
- **Nový namespace:** musíš ho přidat do `ROOT_NAMESPACES` v `root.tsx`, jinak `bundles[ns]` bude `undefined` a `t()` vrátí dotted-path místo textu.
- **Měna:** ceny jsou Kč i v EN/HU/SK (provoz je CZ-only). Suffix `Kč/měs` se překládá (`CZK/mo`, `Kč/hó`, …) ale částka zůstává.
